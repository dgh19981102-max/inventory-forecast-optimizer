# 项目讲解（中文，给自己看 / 面试用）

目标：每一步做了什么、为什么这么做、结果怎么解释，都能用自己的话讲清楚。

---

## 1. 一句话讲清楚

> 输入一张 Excel（商品、成本、库存、历史销量），输出每个商品未来 6 周每周订多少货，并用真实历史需求回放证明：在写明的成本假设下，比"按上月销量补货"总成本低约 39%，缺货 SKU-周少 66%。

## 2. 整体流程

```
历史销量 ──► 预测（5 个模型，滚动回测选最好的）──► 点预测 + 过去误差的分布
                                                        │
                                                        ▼
            成本/约束（Excel） ──► 混合整数规划（MILP）──► 本周订单 + 未来几周计划
                                                        │
                                                        ▼
                                  用真实需求逐周回放（滚动计划）──► 成本对比
```

## 3. 数据

- **来源**：UCI Online Retail II，英国一家礼品批发电商 2009-12 到 2011-12 的约 107 万行交易，CC BY 4.0 许可。
- **清洗**：
  - 两个 Excel sheet 在 2010-12-01 到 2010-12-09 有 9 天重叠，要去掉重复部分。
  - 去掉取消单（发票号以 C 开头）、退货（数量 ≤0）、价格为 0 的行、完全重复的行，以及非商品编码（POST 邮费、M 手工调整等）。
- **汇总**：按周一开始的周汇总，没卖出就记 0。圣诞节全店歇业的周，在拟合模型时用前后周的平均值填充，因为店家知道自己哪几周关门，模型不该学成"圣诞需求暴跌"。
- **挑选商品**：95% 以上的周有销量、周均 ≥40 件，再选波动系数（标准差/均值）最小的 30 个。
- **可能被问的弱点**：挑商品用到了全期数据，算轻微的"偷看未来"。这么做是为了保证商品覆盖完整的生命周期，README 里已经写明。

## 4. 预测

**4.1 五个模型**

1. **季节性朴素**：用去年同一周的销量。
2. **4 周移动平均**：相当于"上个月平均"。
3. **ETS（Holt 阻尼趋势）**：在 log(1+销量) 上做。
   - 为什么取对数：批发会有偶发的大单，取对数后一张大单不会把水平线拉高好几周。
   - 为什么不加 52 周季节项：只有两年数据，估不稳。
   - 提速做法：每 4 周用 statsmodels 重新估一次参数，中间几周用同一组参数直接递推，结果和 statsmodels 完全一致（有单元测试验证）。
4. **LightGBM**：所有商品共用一个模型，每个预测步长 h 单独训练一个（直接多步预测）。
   - 特征：过去 8 周销量、4/8 周均值、13 周标准差、去年同周销量、去年同周相对去年水平的比值、目标周是一年中的第几周。
   - 所有特征都除以该商品最近 13 周的平均水平，这样大小不同的商品可以放进同一个模型。
   - 损失函数用 L1（预测中位数），对大单更稳健，也正好对应 WAPE 这个指标。
5. **Ensemble**：ETS 和 LightGBM 取平均。

**4.2 滚动回测**

- **做法**：站在第 52 周，只用之前的数据预测未来 1–6 周；往前挪一周再预测，一共 47 个起点。单元测试会改动起点之后的数据，确认预测结果不变，以此证明没有偷看未来。
- **WAPE**：Σ|预测−实际| / Σ实际。比 MAPE 更适合销量数据，因为 MAPE 在销量很小时会爆掉。

| 模型 | WAPE |
|---|---|
| Ensemble | 48.5% |
| ETS | 49.1% |
| LightGBM | 49.9% |
| 4 周移动平均 | 50.7% |
| 季节性朴素 | 73.5% |

- **怎么解释**："单个批发商品的周销量噪声很大，最好的模型只比移动平均好约 4%。所以这个项目的价值不在把点预测做得多准，而在量化不确定性，并据此做决策。"
- **预测区间**：用过去误差（实际/预测）的分位数乘以点预测，得到 P10–P90 区间。实际值落在区间里的比例是 82–84%（目标 80%），说明区间是诚实的。

## 5. 优化模型（这部分一定要能讲）

**变量**（i = 商品，t = 周，s = 情景）：

| 变量 | 含义 |
|---|---|
| `n[i,t]` | 订几箱（整数），订货量 Q = 箱规 × n |
| `y[i,t]` | 这周订不订（0/1） |
| `I[s,i,t]` | 情景 s 下的周末库存 |
| `U[s,i,t]` | 情景 s 下没能满足的需求，按丢单处理，不会延后补发 |
| `O[t]` | 超出仓库容量、需要临时租用的空间 |

**约束**：

- **库存平衡**：本周末库存 = 上周末库存 + 本周到货 − 需求 + 丢单量。本周到货是 L 周前下的单，L 就是交货周期。
- **丢单不能超过需求**：U ≤ D。
- **仓容**：周初库存占用的空间 ≤ 仓库容量 + O。这是"软约束"，超出部分按租用空间付费，保证模型永远有解。
- **预算**：每周进货金额 ≤ 预算。
- **起订量和固定成本**：MOQ·y ≤ Q ≤ M·y。不订就是 0；要订，至少订到起订量，并付一次固定成本。

**目标**：最小化 固定订货成本 + 期望持有成本 + 期望缺货惩罚 + 超容成本。

**为什么目标里没有进货单价**：卖出去的每一件都要按同样的单价买一次，早买晚买单价一样，不影响决策。现金占用由预算约束控制，持有成本里也包含了资金成本。面试常被问到这一点。

**两个版本**：

- **点预测版**：只用一个情景（点预测），再加一个软的安全库存目标：z × σ × √(交货期+1)。z 由服务水平决定，95% 对应 1.645；σ 是该商品过去一周预测误差的标准差。
- **情景版**：用 14 个带权重的需求情景，同一套订货计划要在所有情景下都算一遍成本，最小化的是期望成本。

**滚动计划**：每周都规划未来 6 周，但只执行第 1 周的订单。下周拿到新的库存和销量后重新规划，和 microgrid 项目里的 MPC 思路一样。

**求解**：OR-Tools 加开源的 SCIP 求解器，约 5,500 个变量。情景版每次 5–30 秒（上限 30 秒，MIP gap ≤ 0.1%），点预测版 1–4 秒。

**建模中踩过的坑（面试时很加分）**：

1. **大 M 要尽量紧**：每张订单的上限取"情景里从到货周到期末的最大需求"。只改这一处，求解就快了约 10 倍。
2. **gap 要设到 0.1%**：目标函数里有一大块"极端情景下怎么都避免不了的缺货"，1% 的相对 gap 可能就是 £30–50，求解器会因此忽略单个商品的订货决策。改到 0.1% 后结果明显变好。
3. **Pyomo 加 HiGHS 太慢**：这个模型的根节点割平面很慢，30 秒内找不到解，所以换成 OR-Tools 加 SCIP。两者都是开源的。

## 6. 情景是怎么生成的（这个项目最有意思的地方）

- **基本做法**：对每个过去的预测起点，记录"实际 ÷ 预测"在 1–6 周后的比值。只用当时已经能看到的误差，不偷看未来。把这个误差分布按分位数切成 14 段：10%、20%……90%，再往尾部切得更细（95%、97.5%、99%、99.7%）。每段取中点作为一个情景，概率就是这一段的宽度。这样 14 个情景就能覆盖到 99.85% 分位，而随机抽 14 个样本很难抽到 95% 以上。

- **第一版为什么输给了点预测版**：校准检查显示，真实需求高于情景 P90 的比例是 17–20%（应为 10%），也就是情景太乐观了。原因有两个：
  1. **每个商品的误差样本太少**（15–40 个），估出来的尾部太薄。
  2. **过去的偏差被带进了未来**：2011 年上半年预测普遍偏高，到 Q4 旺季预测又偏低。

- **修正**：
  1. **所有商品合用一个误差分布**（几百个样本），尾部更稳。
  2. **以中位数为中心**：去掉过去的平均偏差，但保留需求"右偏"的形状。

  修正后，超过 P90 的比例降到 8–10%，情景均值和实际之比约 1.01。

- **试过但更差的方案**（README 里有完整的表）：
  - **两阶段 recourse**（未来几周的订单可以随情景不同）：求解快 5 倍，但模型以为自己以后总能完美应对，于是囤货，超容成本暴涨。
  - **Latin hypercube 随机情景**：也比默认方案差。

  把这些失败的尝试也写出来，说明结果不是挑出来的。

## 7. 仿真对比和结果

**对比规则**：

- **起点相同**：三种策略的初始库存都一样。
- **只看过去**：每周决策时只能用之前的数据。
- **真实需求**：需求用 2011 年 6–11 月真实发生的数据。
- **丢单**：没货就丢单。
- **成本口径**：固定订货费 + 持有成本 + 缺货惩罚 + 超容费用。

**经验法则**：每周把"库存 + 在途"补到"最近 4 周平均 × (交货期 + 2) 周"，按整箱向上取整，不足起订量就按起订量下单，超预算就按比例砍单。

| 策略 | 总成本 | 缺货 SKU-周 | 下单次数 |
|---|---|---|---|
| 经验法则 | £16,758 | 59 | 514 |
| 经验法则（事后调到最优参数） | £12,852 | 13 | 502 |
| 点预测 + 安全库存 | £10,422 | 16 | 259 |
| 情景优化 | £10,261 | 20 | 198 |

**怎么解释这张表**：

1. **钱主要省在哪**：大头是"批量订货"，下单次数从 514 降到 198，固定成本少了一大半。其次是在共享的预算和仓容下合理分配，缺货大幅减少。
2. **为什么要放"事后最优"那一行**：即使经验法则的参数事后调到最优（现实中做不到），优化版仍然便宜 20%。这是为了避免"拿一个很差的基准来比"的质疑。
3. **两个优化版的差距**：测试期只差 1.5%，在求解时间上限带来的波动范围内。在完全没参与设计的留出期（2011 年 3–5 月），情景版比点预测版低 8%，比经验法则低 42%。
4. **对假设的敏感性**：结论依赖成本假设，尤其是每次下单的固定成本（£15）。敏感性分析见 README。

## 8. Excel 进出

- **输入模板**：`examples/input_template.xlsx`
  - Settings：仓容、预算、规划周数等
  - Products：每个商品的成本、箱规、起订量、交货期、现有库存、在途
  - DemandHistory：每周销量，至少 60 周
- **输出**：`output_plan.xlsx`
  - Summary：本周要下几单、花多少钱，以及三种方案的成本对比
  - Order Plan：每个商品每周订多少，第 1 周 = 本周要下的单
  - Plan Detail：每个商品每周的 P10/P50/P90 预测、订单、到货、预计库存
  - Forecast Accuracy：回测结果，说明为什么选了这个预测模型
- **三种方案的对比方法**：在 500 个按历史误差随机抽的需求情景下，计算三套计划各自的期望成本。这些情景和优化时用的 14 个情景不同。
- **换数据**：同格式的新 Excel 可以直接出方案，有单元测试覆盖这一点。

## 9. 面试 / 客户常见问题

| 问题 | 回答要点 |
|---|---|
| 节省 39% 可信吗？ | 是在写明的成本假设下、用真实需求回放得到的；和事后调到最优的经验法则比也省 20%；留出期 42%；每次下单固定成本从 £5 改到 £30，结论方向不变（见 README）。 |
| 为什么不用深度学习？ | 每个商品只有约 100 周数据；LightGBM 只比移动平均好 2%，深度学习不会有质的提升。价值在不确定性加决策这一步。 |
| 交货期不确定怎么办？ | 可以把交货期也做成情景，比如 30% 概率晚一周，在库存平衡里按情景安排到货，模型结构不变。 |
| 商品多到几千个怎么办？ | 只有预算和仓容把商品耦合在一起。可以用拉格朗日松弛按商品分解，或者先按 ABC 分类，只对 A、B 类做精细优化。 |
| 为什么目标里没有进货价？ | 见第 5 节：单价不随时间变，不影响决策；资金由预算约束控制，资金成本在持有成本里。 |
| 缺货惩罚怎么定？ | 丢掉的毛利，加上 10% 售价作为商誉损失。客户可以在 Excel 里自己改。 |
